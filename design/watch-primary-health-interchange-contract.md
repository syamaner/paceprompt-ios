## Scope, compatibility and architecture gate

Minimum API baseline: iOS 17 and watchOS 10. Existing iPhone-only saving, summary schemas 1/2 and PacePrompt JSON format 1 retain their current meaning under the [iPhone export contract](apple-health-workout-export-contract.md). This specification neither migrates their records nor changes production behaviour. Watch-owned records need an explicit versioned ownership envelope in #115; absence on historical records means historical iPhone behaviour, never inferred Watch ownership. Missing or malformed ownership in a new Watch-capable record is invalid and save-suppressed; it must never be reclassified as historical absence. Never convert an already-started iPhone-owned attempt to Watch ownership.

Responsibilities and dependency direction:

| Boundary | Responsibility and contract |
| --- | --- |
| Pure ownership/manifest domain | Immutable identity, writer exclusion, revisions, prefix validation, completion and failure decisions; no Apple SDK, filesystem, transport or UI types |
| iPhone orchestration | Owns execution, accepted targets, separately observed values, local History and final manifest; emits recording-state requests only from accepted execution observations |
| Watch orchestration | Owns primary session, builder, collection, terminal assembly and sole finish; coordinates durable ownership and bounded manifest state |
| Consumer-owned adapters | Protected ownership journal, mirror sender, Watch builder/store and reader statistics ports; serialize HealthKit callbacks into the domain |
| Presentation | Shows local execution, Watch recording, mirror and save state independently; cannot turn HealthKit state into a treadmill command |
| WeeklyHealthReport | Optional recognized-metadata decoder plus statistics projection; independent source code and explicit user-controlled export |

Composition roots supply clocks (UTC and monotonic), IDs, persistence, transport and stores. Alternate adapters must pass the same fake-store contract tests below. Extension points are transport, storage and statistics acquisition; writer identity, provenance, interval immutability, absence semantics and schema interpretation are closed/versioned invariants. No generic repository abstraction or additional delivery channel is required. #115 must enforce that Watch/mirror code has no dependency on a treadmill-command capability.

## Ownership and state transitions

Before requesting Watch creation, the phone durably reserves a fresh summary UUID as `watchPrimary` in its protected ownership journal. This is the point of irrevocable iPhone Health-save suppression for this attempt, including UI, service, retry, crash recovery and History. Reserve failure sends nothing. Phone may then launch the companion using the HealthKit launch API. Watch creates at most one prepared, unbound primary session/builder to establish mirroring, but starts no collection yet. Its protected startup journal and active-session recovery prevent a duplicate launch from creating another primary. Over the mirror, phone sends `bind` for its reserved summary; Watch durably binds that identity before beginning recording. A busy/already-bound Watch rejects a different summary. Failure to bind discards the unrecorded prepared session. Ambiguous startup never creates another primary. After the actual session-start callback Watch returns `bound` with the immutable start date; phone must receive that matching response before beginning this Watch-assisted execution. Creation and its ambiguous outcomes are journalled; retry never creates a second builder. A lost ownership response leaves the phone suppressed, not free to save. Starting a separate iPhone-only attempt requires a new explicit user action and new summary ID after the first attempt is terminal; it is never a fallback copy.

No ownership transfer, app-driven automatic remirroring, automatic treadmill reconnect, durable message queue or WatchConnectivity channel exists in v1. Revision 1.2 permits HealthKit OS redelivery of the same primary session under the [durability amendment](watch-durable-recovery.md): validate activity, immutable start and reserved summary again, never restart execution. Register one phone handler at app construction and retain it across foreground/background transitions. Watch recovery restores the existing active session/delegates/builder through Apple's recovery API; if identity, journal or builder reconciliation is uncertain, quarantine saving as ambiguous. Never create a replacement session to repair uncertainty. Journal only identity, ownership, bounded intervals, revisions and result state; no raw sensor values in PacePrompt History. #115 must version retention and protected deletion with that envelope, including a suppression marker for every retained Watch-owned summary. Revision 1.2 adds explicit verified-stop and retirement controls: archive the uncertain journal immutably, persist retirement, and allow only a new explicitly reserved identity. Never retry the retired identity or claim its save was absent. See the durability amendment for bounded retention, storage-failure and callback-fencing rules.

| State/event | Phone action | Watch action/result |
| --- | --- | --- |
| New explicit Watch-assisted attempt | Persist reservation, suppress iPhone save | Request scoped permission; prepare primary once, mirror, bind reservation, then begin recording |
| Permission denied / creation definitely fails | Preserve ownership and local facts; show unavailable | No workout saved; no automatic retry/fallback |
| Mirror established | Retain matching mirror; send cumulative state | Collect available Watch metrics; acknowledge applied manifests |
| Duplicate ownership/start callback | No new attempt | Return existing state; no new builder |
| Accepted treadmill stationary/pause observation | Request HealthKit recording pause once | Await session callback; expose recording state independently |
| Accepted execution resumes after required observation | Request HealthKit recording resume once | Await callback; no target change |
| Watch/HealthKit pause, resume, end, error or connectivity callback | Update recording UI only; existing execution safety policy remains independent | Recording transition only; emit no FTMS effect |
| Duplicate/delayed recording request | Ignore stale sequence; no replay after end | Apply newest valid recording request only; callback is recording evidence |
| Closed interval / final execution record | Send immutable cumulative revision | Validate/stage prefix; acknowledge applied revision |
| Mirror disconnect | Invalidate mirror; preserve local record and suppression | Continue available Watch collection; completion remains unconfirmed unless final confirmation was already accepted |
| Phone execution fails/interrupted | Preserve truthful closed intervals; declare terminal outcome | May save a nonempty valid prefix as incomplete; discard if empty; no claim that the local attempt became successful |
| Final manifest acknowledged to phone | Send `finalize` referencing exact revision | Confirm only matching applied final revision, then begin terminal assembly |
| Watch End without final confirmation | No treadmill action | End recording immediately; save a nonempty valid prefix as incomplete, otherwise discard |
| Terminal assembly error before finish | Never save on phone | Discard builder on definite error; show failed, no replacement builder |
| `finishWorkout` returns non-nil workout | Keep “Watch-owned; save result unavailable on iPhone” | Mark saved; one finish operation |
| Finish error/nil/locked-device uncertainty or Watch receipt persistence failure | Show unknown, keep suppression | `saveAmbiguous`; never infer absence or retry finish/create automatically |
| Recovered active workout with provable journal | Keep suppression; OS same-session redelivery only | Restore existing primary; continue incomplete if completion proof unavailable |

Human console and safety key remain authoritative. No Watch/HealthKit event emits Request Control, Start, Stop, Pause, resume, target restoration or retry. Requests to pause/resume recording can originate only from the already accepted phone execution observation stream, never speed guesses, HealthKit callbacks or transport receipts. End recording cannot stop the belt; the UI must state this when relevant. Unknown treadmill state stays unknown. No accepted execution or FTMS semantics change in this slice.

## Cumulative wire protocol v1

UTF-8 JSON objects, no duplicate keys, finite numbers, exact declared fields, integer versions/revisions (not booleans), UTC timestamps with millisecond precision (`YYYY-MM-DDTHH:mm:ss.SSSZ`). Decimal target/observation values remain decimal numbers and map to `NSDecimalNumber`; never locale strings or binary floating-point tails. Identity is a lowercase UUID. Times are facts from the named source, not repaired to fit another clock. A cross-device clock mismatch that places an interval outside the Watch workout makes interchange incomplete; never clamp it.

Every message contains `schemaVersion: 1`, `summaryID` and `kind`. Messages from another summary/session are rejected. Message kinds:

| Kind/direction | Additional fields |
| --- | --- |
| `bind` phone → Watch | `workoutActivity` = `indoorWalking` or `indoorRunning`; repeat same binding returns its state; another binding is rejected |
| `bound` Watch → phone | `workoutStart` = actual Watch session-start callback UTC boundary; confirms persisted summary and active recording |
| `manifest` phone → Watch | `revision` positive integer; `workoutActivity` = `indoorWalking` or `indoorRunning`; `workoutStart` = agreed Watch session start; `intervals` array; `final` boolean; `workoutEnd` = null until final, then agreed terminal recording boundary; `localOutcome` = null until final, then `completed`, `stoppedByUser`, `failed` or `interrupted`; `distance` as below |
| `ack` Watch → phone | `revision` = highest atomically applied revision, initially 0; does not mean HealthKit saved or packet durably delivered |
| `prepareEnd` phone → Watch | positive `sequence` in the same stream as recordingState; explicit end preparation after terminal local execution |
| `endPrepared` Watch → phone | matching `sequence`; `workoutEnd` = Watch UTC end boundary (pause callback, or preparation instant if already paused, as specified below); same duplicate request returns the frozen boundary |
| `finalize` phone → Watch | `revision` = final revision whose matching ack the phone received; acknowledgement confirmation, not treadmill authority |
| `recordingState` phone → Watch | positive `sequence`; `state` = `paused` or `running`; `observedAt` = accepted execution observation time; requests HealthKit recording state only |

Ownership binding uses the matching mirrored session plus the previously reserved summary ID. `bind`/`bound` are part of v1; do not derive the reservation from a HealthKit UUID. Duplicate bind while startup is pending cannot repeat begin-collection; respond only once the original start result is known. No manifest is accepted until bound, and `workoutStart` must equal that recorded callback date. A 30-second injected monotonic startup deadline applies; expiry before binding discards the unrecorded primary, and expiry after possible start becomes unavailable/ambiguous to the phone with suppression retained. The Watch user may explicitly end any primary that did start; it saves incomplete only with a nonempty materializable prefix, otherwise discards. No fixture message authorizes real execution. A live transport send completion is never an application ack.

Each interval has exactly the JSON fields in the fixtures: `segmentIndex`, `intervalIndex`, `startedAt`, `endedAt`, `prescribed` (kind, speed, inclination), independent `effectiveSpeed` and `effectiveInclination` values/sources, `settledObservation` (time, speed, inclination, provenance), and `endReason`. These inherit the [version-2 interval semantics](apple-health-workout-export-contract.md#logical-segments-and-executed-intervals). Indices are nonnegative integers; first interval of a segment is 0, subsequent ones increment by 1; segment indices increase or stay equal (skipped unexecuted plan segments are permitted). Stable identity is `(summaryID, segmentIndex, intervalIndex)`, not array offset or HealthKit-generated activity UUID. Prescribed kind is `warmUp`, `interval`, `recovery` or `coolDown`; sources are `planned` or `manualOverride`; observation provenance is `fr30zTreadmillDataCurrentEpoch`. End reasons are `planTransition`, `targetChanged`, `paused`, `completed`, `endedByUser`, `interrupted`, `failed`. Observed timestamp is the interval start; never copy target fields into observations.

Validate the entire envelope before mutation: nonempty duration, chronological order, no overlap, same type, within known workout bounds, complete observed fields, unique interval identities and immutable prefix. Every newer revision contains every earlier interval unchanged, then zero or more new closed intervals. A higher cumulative revision may skip a lost revision. Lower revisions are ignored; same revision/same decoded content re-acks without mutation; same revision/different content or any rewrite/truncation is a conflict and latches incomplete. Malformed/unsupported content is rejected without advancing the applied revision and latches incomplete for that interchange. Preserve the last good prefix. Once a final revision is applied, no newer revision is accepted. Gaps for target settling and physical pause remain gaps.

“Applied” means validated bounded state and its journal are atomically accepted on Watch. Do not call builder activity mutation per incoming message. Stage the full prefix, then materialize each activity exactly once during terminal assembly; the Watch acknowledges staged domain state, not an unsaved HealthKit result. The store adapter verifies no auto-generated/overlapping extra activities remain in the final mapping. If this cannot be achieved with the live builder on signed devices, #115 must stop and amend this contract, not claim completeness.

Limits: maximum 32,768 encoded bytes per message and 64 intervals per manifest, whichever is reached first. Each sender uses a monotonic rolling ten-second byte budget of 65,536 across all message kinds. Nonfinal manifests use at most 24,576 bytes in any rolling ten seconds and at most one send per five seconds; coalesce pending nonfinal manifests to the latest cumulative state. A larger cumulative manifest is held for terminal delivery, not truncated. Reserve 32,768 bytes for the first final manifest and 8,192 bytes for bounded control/ack messages. Control messages are at most 512 bytes, duplicates are coalesced, and at most 16 are sent per rolling ten seconds. The first final manifest is exempt from nonfinal pacing and sent from the reserved terminal budget. If control pressure or a retransmission would exceed its allocation, drop/coalesce it; deadline expiry remains incomplete. No final retransmission is required during the five-second deadline. This guarantees a nonfinal send immediately before end preparation cannot itself consume the final-manifest byte budget or pacing window. A connected sender may retransmit the unchanged latest unacknowledged manifest within those limits. No fragmentation/truncation. Oversize/overflow latches incomplete while local History remains complete; stop sending interval manifests for that attempt. Repeated malformed input is dropped without unbounded errors or logging payloads. Counters and sequences are positive signed 64-bit integers; overflow is incomplete, never wraparound. Transport backpressure cannot delay a safety operation or local execution.

### Finalisation and acknowledgement loss

Before ending a connected session (which stops mirroring), phone publishes final revision N, receives `ack(N)`, then sends `finalize(N)`. Watch may mark the interchange complete only if N is its applied final revision, it received that confirmation, no integrity failure is latched, the local outcome is `completed` or `stoppedByUser`, and every final interval can be materialized in the final workout bounds. An empty materializable interval set is discarded, never finished or saved. Neither send success nor the Watch's own ack transmission proves phone receipt.

Phone's final message must use the Watch-confirmed recording end boundary agreed during explicit end preparation while the mirror is still live; end preparation pauses HealthKit collection through the session API and observes its callback, without treadmill action. #115 must fake-test this ordering and physically verify it; a missing/uncertain end boundary forbids complete interchange. The Watch starts a five-second monotonic deadline on receipt of `prepareEnd`, including waiting for the pause callback. Once preparing end, ignore recording resume and new prepare sequences; replay the frozen endPrepared result for the original sequence. If already paused, use the newly observed preparation instant as the recording end (not the earlier pause date), preserving the existing pause event. When a running session was asked to pause, an absent pause callback makes the agreed boundary unavailable and finalisation incomplete. The phone also uses a five-second deadline from sending prepareEnd and never reports completion from that timeout. After expiry, Watch ends recording and saves a nonempty prefix as incomplete (or discards an empty prefix), without waiting for messages; late confirmation cannot upgrade saved metadata. User Watch End, error or disconnect may end immediately. A Watch receiving no end preparation may continue its primary recording until the user ends it, then save incomplete only with a nonempty materializable prefix, otherwise discard. A final confirmation accepted before disconnect may still save complete if assembly succeeds. No distributed receipt claims exactly-once delivery.

Final assembly: freeze status and prefix, end recording/collection at the actual agreed boundary, validate all intervals against the actual containing workout, add closed same-type indoor activities, optional one distance sample and workout metadata, then finish once. Invalid out-of-bounds prefix cannot be rewritten: omit that interval and subsequent intervals and mark incomplete with the last materializable prefix. If the materializable prefix is empty (including no manifest or all intervals excluded), end the session and discard the existing builder without calling finishWorkout. Persist a definite no-workout-saved result only when discard is certain; otherwise quarantine as ambiguous. Only after definite discard, display “Workout not saved: no execution intervals were received or usable.” For uncertain discard, display an ambiguous save result, never definite absence. Never synthesize an interval or save on iPhone. Discarding the workout does not promise deletion of sensor samples HealthKit may already have saved. Metadata failure or activity-add failure discards the builder on a definite pre-finish failure. Ambiguous builder mutation/finish quarantines the attempt; no destructive compensation, replacement workout or automatic retry. Watch persists/displays a successful receipt only for a returned workout. If Watch receipt persistence fails, quarantine as saveAmbiguous rather than retry. Because ending the session stops mirroring before finish, v1 has no final-result delivery to iPhone: the phone retains “Watch-owned; save result unavailable on iPhone” even after a successful final-manifest acknowledgement/confirmation. Watch alone retains the actual receipt; consult Watch or Apple Health for the result. No new message kind or alternate delivery mechanism is implied. Saved status never rewrites local execution facts. Workout duration is HealthKit pause-adjusted recording duration; local active duration remains the sum of executed intervals. They can differ during settling, delayed callbacks or independent Watch pause.

## Frozen HealthKit metadata

Full namespaced key = `com.otherweather.PromptPace.` plus suffix below, case-sensitive. Unknown values do not silently become supported v1. Workout custom values are `NSString` or integral `NSNumber` unless stated otherwise:

| Suffix | Type/value |
| --- | --- |
| `interchangeSchemaVersion` | integer `1`, independent of timeline schema and WeeklyHealthReport document schema |
| `summaryID` | lowercase UUID string; explicit identity, never parse sync identifier |
| `ownership` | string `watchPrimary` |
| `interchangeStatus` | string `complete` or `incomplete` |
| `manifestRevision` | integer >= 0, highest applied revision (0 means none) |
| `intervalCount` | integer 1–64 for a saved workout, count of activities actually materialized; reader must match the count before claiming a complete mirror |
| `distanceProvenance` | string `fr30zCumulativeDistanceDelta` only when one sample included; otherwise `unavailable` |

Workout `HKMetadataKeySyncIdentifier` = `com.otherweather.PromptPace.workout.<summaryID>`; optional distance sample uses `com.otherweather.PromptPace.distance.<summaryID>`. Both `HKMetadataKeySyncVersion` = integer 1 in v1, independent of manifest revision. This initial Watch contract has no replacement/retry save. Future replacement must be separately versioned and verified. Sync keys are secondary defence, never two-writer permission.

Each recognized activity reuses **all 15 keys and types** in the [existing timelineSchemaVersion 1 mapping](apple-health-workout-export-contract.md#apple-health-interval-mirror), without renaming or reinterpreting them. It additionally requires `com.otherweather.PromptPace.summaryID` (same UUID string as containing workout). `timelineSchemaVersion` = integer 1, indices integer, targets/observations decimal `NSNumber`, `observedAt` `NSDate`, and kind/source/provenance/end-reason strings have the enums above. The paired fixture uses UTC strings for `NSDate` and symbolic names for Apple's sync constants; adapters map those to SDK constants, not literal placeholder keys. Activity configuration is the parent's walking/running type and indoor location. HealthKit's activity UUID is retained as reader identity separately from stable PacePrompt interval identity.

No plan prose, user-entered name, peripheral identity, raw packets, command evidence or arbitrary metadata crosses this boundary. Neither targets nor a settled observation become speed, inclination, elevation or average-speed HealthKit quantity samples.

## Metrics and single-source distance

Heart rate (minimum/average/maximum beats per minute) and active energy (cumulative kilocalories) come only from the Watch/HealthKit data source. Availability depends on configuration, permissions and device. Energy is a HealthKit calculation/estimate. Missing values remain `noDataOrAccess`, never zero or inferred denial. A real reported zero can remain zero. Use `HKWorkout.statistics(for:)` with `healthKitWorkoutStatistics` provenance and `HKWorkoutActivity.statistics(for:)` with `healthKitActivityStatistics`; preserve each independently available HR statistic. HealthKit may interpolate samples across activity boundaries; do not claim PacePrompt measured per-interval energy. No raw HR export/query fan-out and no raw sensor persistence in PacePrompt History.

Disable automatic `distanceWalkingRunning` collection on the Watch source **before collection begins** and verify no other source contributes. At finalisation add at most one positive accepted `fr30zCumulativeDistanceDelta` aggregate in metres, and only if distance write authorization, same connection epoch, nonregression, accepted boundaries and source exclusion all remain established. Wire `distance` is either `{ "state": "unavailable" }` or `{ "state": "accepted", "metres": <positive decimal>, "provenance": "fr30zCumulativeDistanceDelta" }`; accepted form is allowed only in the final manifest. iPhone validates the aggregate's existing local boundary evidence before sending; packets, connection identifiers and cumulative samples are not transmitted. A final manifest alone is insufficient: Watch also validates its collection configuration and authorization.

If final confirmation is missing, distance unavailable/zero/reset, authorization absent or source exclusion uncertain, omit the distance sample and use `distanceProvenance = unavailable`. Never add both Watch and treadmill distance. If unwanted automatic distance has already entered a builder and omission cannot be guaranteed, do not save that builder: fail closed/discard before finish, or mark ambiguous if mutation is uncertain. Do not save combined distance with an “unavailable” label. This uncertainty requires a contract/adapter repair before release. Local accepted distance remains authoritative and unchanged. Never publish per-activity distance interpolated from the workout aggregate, or derive any distance from speed × time.

## WeeklyHealthReport schema-v4 reader boundary

The fixture bundle below is a **contract projection**, not an entire Daily document or a second workout format. #80 adds these semantics as optional workout enrichment in its independently owned schema-v4 document. Existing v3 golden files, basic non-PacePrompt workouts, deterministic key ordering, UTC encoding, units, half-open daily membership and daily active-energy aggregates stay meaningful. Daily energy is never a source for workout energy or summed again with it.

Decode only recognized keys. Recognition states: `notPacePrompt` (namespace absent), `supportedComplete`, `supportedIncomplete`, `unsupported` (unknown version/ownership/enum), `invalid` (malformed known schema). Keep basic workout and available HealthKit statistics for every state. Preserve unsupported schema number only when well typed; do not dump unknown metadata. Complete status requires recognized consistent workout AND activity metadata, identity, types, bounds, ordering, unique interval identities and a visible activity count equal to intervalCount. An incomplete source stays incomplete even if its visible prefix looks plausible. Reader loss/malformed/missing required metadata cannot upgrade it. #80 must not infer missing intervals from any other source or label its export a complete physiological record.

Export chronological activities with stable HealthKit activity ID, start/end, HealthKit pause-adjusted duration, configuration when visible, bounded statistics and recognized interval metadata. An absent activity end is invalid for a completed PacePrompt mirror, not filled from duration. Keep supported incomplete prefix metadata when valid and label the whole mirror incomplete. For recognized Watch-primary v1 enrichment, workout distance is available only when recognized distance provenance and the workout's distance statistic both exist; absent read visibility remains `noDataOrAccess`. Do not read per-activity distance or reconcile sources. Non-PacePrompt and historical iPhone-only workouts retain their existing reader semantics; absence of the new Watch provenance key does not retroactively invalidate them. Arbitrary metadata and raw samples are excluded.

Prefer already materialized workout/activity statistics: no new HR/energy query per workout/activity. Preserve #50's coherent snapshot, cancellation and bounded fan-out. Infrastructure errors abort publication; unavailable/unsupported enrichment remains an explicit value. No partial Daily JSON publication on error/cancellation. This contract does not add HealthKit read permission to PacePrompt or any HealthKit write/delete to WeeklyHealthReport.

Before releasing #80, the explicit Daily Export preview must disclose **workout heart-rate summaries, HealthKit-calculated energy and PacePrompt execution intervals**, available/missing fields and the reviewed Google Drive destination/canonical-file replacement.
