Product concept

FR30z treadmill controller

A local-first iPhone and Apple Watch app that converts natural-language interval workouts into validated plans, controls the Reebok FR30z through Bluetooth FTMS, and saves one meaningful workout to Apple Health.

01 · App structure

Four persistent destinations

The persistent tab bar should contain Home, Plans, History and Settings.

Import opens from Home or Plans. Selecting a plan opens a preflight screen, then Exercise takes over the full screen. Exercise should not be a normal tab because accidental navigation during a workout would be undesirable.

Plan compilerNatural language to validated local plan.
Session runnerTimeline, Bluetooth control and live display.
Workout recorderLocal detail plus one HealthKit workout.
02 · Home

Operational, not dashboard-heavy

  • Treadmill, Watch and Apple Health readiness.
  • A large Start workout button.
  • An Import workout button.
  • Recently used plans.
  • Last-seven-days sessions, workout time and distance from this app.

Calories should be omitted unless Watch-derived active energy is available.

03 · Plans and import

LLM-assisted, locally controlled

Paste free text
Strict schema response
Local validation
Readable preview
Name and save

Only the pasted workout text and the schema should be sent to OpenRouter. The result must then pass deterministic local validation before it can be saved or executed.

The canonical schema should contain a version, suggested name, indoor walking or running activity, and segments with a label, duration, absolute target speed and absolute target inclination.

The app calculates timestamps and totals. The model should not perform timeline arithmetic. Raw JSON can live under “Technical details”; the normal preview should be a readable interval timeline with totals, assumptions and warnings.

OpenRouter supports strict JSON Schema responses for compatible models. Schema compliance improves reliability, but it does not establish that a workout is safe or within the treadmill’s limits.

04 · Settings

Connections, safeguards and privacy

Treadmill

  • Connected machine and connect/disconnect.
  • Discovered FTMS capabilities and ranges.
  • Automatic speed and inclination ceilings.
  • Maximum permitted change between intervals.
  • Foreground auto-connect and diagnostics.

OpenRouter

  • API key stored in the iOS Keychain.
  • Structured-output-capable model.
  • Test connection.
  • Require zero-data-retention routing.
  • Optional European endpoint and delete key.

Health and Watch

  • Apple Health authorisation.
  • Apple Watch companion status.
  • Save completed workouts.
  • Default activity type, confirmed before starting.
  • HealthKit save diagnostics.

Experience and data

  • Metric or imperial display.
  • Audio and haptic interval cues.
  • Keep the display awake during exercise.
  • Export or delete local history.

After a connection loss, the app must read the treadmill’s actual state again. It should never automatically resume a programme merely because Bluetooth reconnects.

05 · Exercise

A glanceable, full-screen operating mode

The central distinction is actual machine state versus requested target. Sending a command is not proof that the treadmill reached it.

  • Current interval, time remaining and upcoming interval.
  • Overall progress.
  • Actual and target speed and inclination.
  • Elapsed time, distance and live heart rate.
  • Treadmill connection and command acknowledgement.
  • Large speed, inclination, Pause and Stop Belt controls.

Stop Belt should act immediately without a confirmation dialog. Ending and saving the workout should be a separate action shown after the belt stops. A temporary pause or Bluetooth interruption should not automatically end the workout.

06 · Apple Watch

Real-time heart rate is feasible

It requires a small watchOS companion app rather than treating Apple Watch as a generic Bluetooth heart-rate strap.

  1. The iPhone starts the Watch app with an indoor walking or running configuration.
  2. Apple Watch owns the primary HKWorkoutSession.
  3. The workout session is mirrored to the iPhone.
  4. Watch collects live heart rate and active energy.
  5. iPhone controls the FR30z and receives its treadmill measurements.
  6. Treadmill-derived data is sent to Watch and added to the workout builder.
  7. Watch finishes and saves the single workout.

Without the companion app, the iPhone cannot simply stream live heart rate from the normal Apple Workout app. A directly paired external heart-rate sensor is the alternative.

Watch distance collection should be disabled or otherwise reconciled when treadmill distance is added, preventing double counting. The result can be one indoor walking or running workout containing meaningful duration, distance, heart rate, active energy and supported detailed samples.

Apple Health is the health record, not the complete telemetry store. The exact plan, inclination trace, Bluetooth acknowledgements and planned-versus-actual comparison should remain in local History.

When a Watch session is active, Watch should finish and save the workout. The iPhone must not create a duplicate workout after receiving the stop action.

08 · History

The detailed, reproducible record

  • Workout name and date.
  • Completed, stopped or interrupted state.
  • Duration and distance.
  • Average and maximum speed.
  • Inclination summary.
  • Heart-rate chart when available.
  • Planned versus executed timeline.
  • Pauses and manual overrides.
  • Apple Health save status.
  • Repeat workout, Export JSON and Delete actions.

The local record should be committed incrementally during exercise so an app crash or disconnected phone does not erase the whole session.

09 · Delivery order

Build risk-first

  1. Confirm FTMS feature flags, measurement decoding and control on the physical FR30z.
  2. Implement a hard-coded, three-segment plan with live state and safe stop behaviour.
  3. Add the deterministic plan model, executor, manual controls and local recovery.
  4. Add Plans, preview, naming and History.
  5. Add OpenRouter import with strict structured output and local validation.
  6. Add the Watch companion and single-workout HealthKit pipeline.
  7. Validate Bluetooth behaviour and Apple Health results on physical devices.
